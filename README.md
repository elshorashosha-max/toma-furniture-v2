# تُومة للأثاث — النسخة التجريبية الجديدة

نسخة مستقلة قابلة للتشغيل محلياً، باللغة العربية وبتخطيط RTL. لا تستبدل الموقع الحالي.

## التشغيل

1. ثبّت Node.js (الإصدار 20.19+ أو 22.12+).
2. شغّل `npm install`.
3. شغّل `npm run dev` وافتح عنوان Vite المحلي.
4. شغّل `npm run build` للتحقق من نسخة الإنتاج.

الصفحات المتاحة: `/` الرئيسية، `/collections` المجموعات، `/collections/:id` تصنيف، `/products` الكتالوج، `/products/:id` تفاصيل منتج، `/cart` السلة، `/checkout` إتمام الطلب، `/wishlist` المفضلة، و`/admin` الإدارة.

## حدود النسخة الحالية

- تُقرأ المنتجات النشطة من `public.products` عبر `@supabase/supabase-js` باستخدام `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`. لا يوجد اتصال حتى إعداد المفتاح العام محلياً.
- تعرض صفحة المنتج الصور مباشرة من `image_url` و`image_urls` دون تحويل روابطها أو تغيير إعدادات Storage.
- السلة والمفضلة محليتان في المتصفح. إتمام الطلب يعيد قراءة المنتجات النشطة والأسعار قبل إرسال الاسم والهاتف والعنوان والإجمالي إلى `orders`، ثم عناصر المنتجات الثابتة إلى `order_items`. لا يعرض بيانات العميل للعامة، ولا يعلن النجاح إلا بعد نجاح طلبي الإدراج. تعذر إتمام العملية بعد حفظ رأس الطلب قد يترك طلبًا دون عناصر؛ تعرض الواجهة رسالة تمنع إعادة الإرسال لتقليل احتمال التكرار، لكن الضمان الذري الكامل يتطلب RPC/معاملة في الخادم.
- صفحة الإدارة تتطلب جلسة Supabase صالحة وعضوية المستخدم الحالي في `admin_users`. تعرض جميع الطلبات على صفحات داخلية، وتقسمها حسب الحالات الفعلية `new`, `confirmed`, `shipped`, `completed`, `cancelled`، مع عدد وقيمة لكل تبويب. تعرض قيمة المكتملة كمبيعات محققة منفصلة عن الطلبات قيد التأكيد، ولا تحتسب الملغاة ضمن المبيعات. تُحمّل بيانات العميل وعناصر الطلب عند فتح تفاصيله فقط. تغيير الحالة يخضع لسياسات RLS الحالية. الحذف يتطلب تأكيدًا ويستفيد من علاقة `ON DELETE CASCADE` المعروفة لحذف العناصر المرتبطة مع الطلب؛ لم تُعدّل سياسات Supabase، لذا قد تمنع سياسة `DELETE` الحالية العملية.
- نموذج المنتج يتيح اختيار JPG وPNG وWebP من الجهاز (حتى 10 ميغابايت للصورة)، والمعاينة محليًا، وتغيير الصورة الرئيسية واستبدال الصور وحذفها وإعادة ترتيبها بالسحب.
- أداة القص المحلية بإطار ثابت 4:3 تتيح التحريك والتكبير وإعادة الضبط ومعاينة النتيجة قبل الاعتماد. القص ينشئ ملفًا محليًا جديدًا بنسبة 4:3 ولا يغيّر الصورة الأصلية أو الملفات المرفوعة قبل التأكيد.
- مسار الرفع في الواجهة يستهدف bucket `product-images` ويتطلب جلسة مدير وعضوية `admin_users`، لكن الرفع يعتمد كذلك على سياسة Storage مناسبة لم يتم تعديلها أو اختبارها. لا تعتبر معاينة الصورة المحلية رفعًا دائمًا؛ عند رفض Storage يبقى نموذج المنتج وملفاته المحلية محفوظة لإعادة المحاولة.
- أُضيف إجراء إزالة المنتج مع تأكيد وفحص عناصر `order_items` المرتبطة. يمنع الحذف عند وجود ارتباطات، ولا يحذف ملفات Storage؛ نجاحه الفعلي يظل خاضعًا لسياسات RLS الحالية.
- تفاصيل المنتج تعرض معرض الصور المصغرة والتنقل بالسحب والأسهم، مع تكبير الصورة والتنقل بلوحة المفاتيح. المنتجات ذات السعر حسب الاتفاق تعرض رابط استفسار واتساب ولا تضاف إلى السلة.
- صور المنتجات في البطاقات والتفاصيل تُعرض داخل إطارات 4:3 باستخدام `object-fit: cover`، وقد تُقص أطراف الصورة بصريًا دون تعديل الملف الأصلي.
- تعرض الصفحة الرئيسية حتى 12 منتجًا نشطًا دون تكرار، مع رابط إلى كامل الكتالوج.
- روابط الشبكات الاجتماعية وواتساب موجودة في تذييل المتجر.
- يستخدم المتجر شعار TOMA Furniture المرفق كما هو؛ لوحة الألوان مستوحاة من الأخضر والبرتقالي والذهبي فيه.
- إذا تعذرت قراءة `products` أو رفضتها RLS، تعرض الواجهة خطأ ولا ترجع إلى بيانات تجريبية أو تحاول تجاوز السياسات.
- مفتاح Supabase المسموح للمتصفح هو `anon` العام فقط. لا تضع `SUPABASE_SECRET_KEY` أو `service_role` أو أي سر في `.env` بادئة `VITE_` أو ملفات العميل.

## إعداد Supabase (بعد مراجعة المشروع القديم)

1. أُنشئ ملف `.env.local` محلياً بعنوان المشروع؛ أضف إليه `VITE_SUPABASE_ANON_KEY` من إعدادات المشروع بنفسك. لا ترسله في المحادثة ولا تضف مفتاحاً سرياً.
2. يعيد العميل قراءة الحقول `id,name,category,description,price,image_url,image_urls,badge,pricing_type,price_text` ويصفّي النتائج بـ `is_active = true`.
3. إذا لم تُعرض المنتجات، راجع صلاحية `SELECT` وسياسات RLS على `public.products` وسجلات الشبكة في أدوات المطور. لا يغيّر التطبيق سياسات RLS أو Storage.
4. ينشئ إتمام الشراء صفوفًا في `orders` و`order_items` باستخدام سياسات الإنشاء الحالية؛ لا يغيّر التطبيق السياسات أو المخطط. حذف الطلبات يتطلب سياسة `DELETE` إدارية، ويظل ممنوعًا للطلبات التي لها عناصر مرتبطة.

## ملفات المشروع

- `src/main.js`: التوجيه والعرض والتفاعلات والصفحات.
- `src/data.js`: تطبيع منتجات Supabase، تنسيق الأسعار، وتصنيفات المنتجات.
- `src/store.js`: السلة والمفضلة المحليتان.
- `src/supabase.js`: تهيئة العميل بالمفتاح العام فقط.
- `src/style.css`: التصميم المتجاوب وهوية RTL.
- `.env.example`: أسماء متغيرات عامة اختيارية فقط.
